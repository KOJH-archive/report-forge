# 공통 발표 자료 제작 지침

이 지침은 Codex, Antigravity, Cursor, VS Code 등 파일을 읽고 터미널 명령을 실행할 수 있는 AI 작업 도구에서 사용합니다. 별도 플러그인 설치나 특정 AI 제공자의 API 키는 필요하지 않습니다. 이 파일의 지침은 자료 제작을 위한 요청에만 적용합니다.

## 사용자 요청 예시

아래 내용을 현재 IDE의 AI에게 전달합니다.

> 이 프로젝트의 README.md와 prompts/BUILD_REPORT.md를 읽어 주세요. 주제는 [주제], 발표 대상은 [대상], 핵심 메시지는 [메시지], 발표 시간은 [시간]입니다. 근거 자료는 [프로젝트 안의 파일 경로]입니다. 공통 원고를 작성하고 데이터를 연결한 뒤 PPT와 Word 보고서, 엑셀 근거 자료를 생성해 주세요. 디자인은 [회사 보고 또는 개인 프로젝트]를 사용합니다.

## 작업 순서

1. `README.md`, `schema/report.schema.json`, `examples/demo/report.json`을 읽습니다. 사용자 자료의 내용을 먼저 확인합니다.
2. 실제 자료가 없으면 사실이나 숫자를 채우지 않습니다. 필요한 근거를 질문하거나, 사용자가 허용한 경우 명확히 표시한 가상 예제를 작성합니다.
3. 발표의 목적과 핵심 메시지를 정리한 뒤 `projects/<이름>/report.json`을 작성합니다. 중요한 결론, 근거, 해석의 범위, 다음 결정이 자연스럽게 연결되도록 합니다.
4. 데이터 파일을 원고 폴더 안에 배치합니다. 원본을 변경하지 않습니다. 복사본을 사용할 때는 실제 출처와 원본의 위치를 기록합니다.
5. 필요한 `sources`, `datasets`, `metrics`를 정의합니다. AI가 계산한 숫자를 직접 옮기기보다 프로그램의 지표 계산 기능과 `{{metricId}}` 치환을 사용합니다.
6. 목적에 맞는 블록을 조립합니다. 모든 페이지에 차트를 억지로 추가하지 않습니다. 수치가 없으면 비교표, 일정 또는 설명 블록을 사용합니다.
7. 주장의 출처와 데이터의 출처를 연결합니다. 개인 해석이나 제안은 근거 사실과 구분해 표현합니다. 짧은 문장과 읽기 쉬운 한국어를 사용합니다.
   회사 PPTX 디자인을 재사용하는 요청이면 `docs/COMPANY_DESIGN.md`를 읽고 `import-template`으로 원고 폴더 안에 가져옵니다. `report.json`의 `template`에 상대 경로와 필요한 매핑을 저장합니다. 자동 분석 결과를 확인하고 지원하지 않는 개체를 분명히 알립니다.
8. `node src/cli.mjs validate projects/<이름>/report.json`을 실행하고 오류를 수정합니다.
9. `node src/cli.mjs build projects/<이름>/report.json --out outputs/<이름>`을 실행합니다. 기존 결과를 갱신하는 작업에서만 `--force`를 사용합니다.
10. `preview.html`을 열어 내용 누락과 페이지 구성을 확인합니다. 실제 Office 파일을 열어 검증할 수 있다면 글꼴, 표, 차트, 출처의 표시를 확인합니다. 검증할 수 없는 범위는 분명히 알립니다.

## 작성 기준

- 회사의 실제 수치, 참고 문헌, URL을 만들지 않습니다.
- 원본 데이터의 단위와 비교 기간을 유지합니다. 계열의 단위가 다르면 차트를 분리합니다.
- 원고와 출처를 함께 관리합니다. 결과 PPT나 Word만 수정하면 다음 생성 시 수정 내용이 반영되지 않으므로 원고에도 변경을 반영합니다.
- 긴 문단은 여러 문단으로, 긴 제목은 제목과 부제로 나눕니다. 글자를 계속 줄이면서 페이지에 끼워 넣지 않습니다.
- `schema/report.schema.json`이 허용하는 속성만 사용합니다. 회사 PPTX 디자인 복제는 안내 문서의 지원 범위를 지킵니다. HTML 미리보기나 Word 보고서에 회사 PPTX 디자인이 동일하게 적용된다고 설명하지 않습니다.
- 특정 IDE에만 있는 도구나 절대 경로를 제품 코드에 추가하지 않습니다. 일반 Node.js 명령과 상대 경로를 사용합니다.

## 결과 전달

원고 위치, 생성한 자료 위치, 핵심 해석, 필요한 사용자 확인을 짧게 알려 줍니다. HTML 미리보기 검사와 실제 Office에서의 표시 검사를 구분합니다.
